## MS-01. 소음 시스템이 어떤 AI에도 연결되지 않음 — **P0 / M**

**문서 근거** — 1.3 이동 소음과 AI 감지:
> 정지 0m 시각만 / 앉아 이동 2m 근접 의심 / 걷기 5m 방향 확인 / 빠른 걷기 8m 1~2초 후 조사 / 달리기 14m **즉시 경계/추격** / 병 깨짐·퍼즐 실패 18m 주변 적 강제 접근

또 GR-1 개요 표의 "핵심 학습 = 걷기·앉기·조명·조사·문서·그림자 퍼즐·첫 Hollow 추격", 6.4 Done 기준:
> 걷기·달리기·앉기·은신·추격 수치와 적 감지 수치가 **실제 플레이테스트로 검증**된다.

**현재 상태** — `noiseRadiusMeters`는 계산되지만 소비처가 사실상 없다.

| 소비처 | 파일:라인 | 실제 효과 |
|---|---|---|
| 값 산출 | `src/application/MovementService.ts:18` | `0 / 2 / 5 / 14` (빠른 걷기 8m 단계 없음) |
| HUD 텍스트 | `src/infrastructure/CanvasRenderer.ts:83` | 숫자 표시 + 14m일 때 색상 변경 |
| 디버그 원 | `src/infrastructure/CanvasRenderer.ts:51` | ``` ` ``` 키를 눌러야만 보임 |
| AI 반응 | `src/application/ChaseService.ts:11` | `pressure = 14m 이상 ? 1.08 : 1` — **속도 +8%가 전부** |

게다가 Hollow는 `chaseRoad` 구역에서만 활성화되므로(`src/presentation/GameController.ts:55-58`, `:121`), 챕터의 나머지 9개 구역에서 소음값은 **소비처가 0개**다.

**플레이 경험 영향** — 문서가 GR-1의 핵심 학습으로 지정한 "앉기/걷기/달리기의 교환"이 게임 안에서 학습될 수 없다. 플레이어가 Ctrl로 앉아 이동해도 얻는 것이 없고(속도만 -40%), Shift로 달려도 잃는 것이 사실상 없다. 문서의 "달리기 = 즉시 경계/추격"이라는 위협감은 재현되지 않으며, 오히려 추격 구간에서는 **달리기가 유일한 생존 수단**(Hollow 174px/s > 걷기 146px/s)이라 문서 의도가 역전되어 있다.

**권고** — 소음 반경을 실제 감지 반경으로 소비하는 `PerceptionService`(Application 계층)를 신설하고, `chaseRoad` 밖에서도 배회하는 Hollow 또는 늑대 연출 트리거가 이 값을 읽게 한다. 최소 스코프로는 "옛 벌목로에서 달리면 동기화 발소리가 가까워진다" 정도의 소프트 피드백만으로도 학습이 성립한다.

## MS-02. 그림자 퍼즐의 실패 규칙 전무 — **P0 / S**

**문서 근거** — 3.3 그림자 교차 퍼즐:
> 실패 | 오답 배치 시 촛불 동시 소등. **3회 오조작 시 발소리와 정신력 -5, 5회 실패 시 힌트 1개 공개.**

**현재 상태** — `src/presentation/ModalView.ts:44-49`. 실패 카운터가 존재하지 않는다. 촛불 소등 연출도, 발소리도, 정신력 감소도, 소음 18m(1.3표 "퍼즐 실패 18m") 발생도 없다. 반대로 **첫 번째 실패에서 곧바로 정답을 알려준다**:
```
'문양은 맞지만 그림자가 갈라져 있다. 거울은 오른쪽 45°, 촛대는 오른쪽 30° 부근에서 겹쳐 보인다.'
```
(`ModalView.ts:48`)

**플레이 경험 영향** — 문서가 설계한 "실패의 대가 → 긴장 상승 → 5회째 구제"라는 압박 곡선이 "1회 실패 → 정답 통보"로 붕괴한다. 챕터 유일의 스토리 퍼즐이 난이도를 잃는다. MS-03과 결합하면 이 퍼즐은 사실상 "버튼을 아무거나 누른 뒤 안내문을 읽는 절차"가 된다.

**권고** — 실패 카운터를 Application 계층(`ShadowPuzzleService`)으로 올리고 3회/5회 분기를 구현. 정신력 미구현 상태라면 3회 페널티는 우선 사운드 + 화면 암전으로 대체 가능(S).

## MS-03. 퍼즐 정답 각도의 인게임 단서 부재 — **P0 / S**

**문서 근거** — 3.3:
> 정답 | 왼쪽 △, 중앙 ○, 오른쪽 ✠ 배치 후 촛대와 거울 각도를 조절해 세 그림자를 하나의 봉인으로 중첩.

문서는 각도의 **구체 수치를 지정하지 않았다.** 즉 각도 정렬은 "그림자가 겹쳐 보이는지"라는 **시각 피드백으로 푸는 문제**여야 한다. 6.4 Done 기준:
> 퍼즐 초기값을 랜덤화해도 문서와 환경 단서의 **추론 논리가 유지**된다.

**현재 상태** — `src/presentation/ModalView.ts:46`:
```ts
const order = slots.join('')==='△○✠'; const aligned = mirror===45 && candle===30;
```
15° 단위 버튼으로 -90~90을 조절하는 UI인데(`ModalView.ts:37-38`), 정답은 **정확히 45와 30 한 쌍뿐**이다. 조합 수는 13×13=169. 그림자가 겹치는 과정을 보여주는 시각 피드백은 존재하지 않으며(퍼즐 UI는 버튼과 텍스트뿐), 각도 힌트를 담은 문서·오브젝트도 월드에 없다(`Chapter1World.ts`의 attic 인터랙션은 `attic.clue`/`attic.puzzle`/`attic.window` 3개뿐).

**플레이 경험 영향** — 문서의 Done 기준을 정면으로 위반. 플레이어는 추론이 아니라 (a) 169회 브루트포스 또는 (b) 1회 실패 후 정답 통보(MS-02) 중 하나로만 통과한다. 랜덤화는 당연히 불가능하다.

**권고** — 둘 중 하나. **(A)** 각도 슬라이더 위에 세 그림자의 겹침 정도를 실시간 표시(예: 중첩률 %, 또는 SVG/Canvas 미니뷰)해서 시각 탐색 문제로 만든다 — 이 경우 랜덤 초기값도 안전해진다. **(B)** 다락 벽 문양이나 관리 기록에 각도 단서를 배치한다. 기획 의도상 **(A)** 를 권장한다(문서의 "그림자를 하나로 중첩"은 시각 문제다).

## MS-04. 진행 게이팅 부재로 "첫 오두막 상태 변화" 루프 우회 가능 — **P0 / S**

**문서 근거** — 00장 개정 요약 표, GR-1 진행 항목:
> 기존 v1: 첫 오두막→관리동 직행 / **최신본 반영: 첫 오두막 첫 방문→관문 확인→첫 오두막 상태 변화/관리 기록→옛 벌목로→둘째 3층 오두막**

3.2 첫 오두막: "첫 방문 안전, **재방문 상태 변화**", 3.4 블록아웃 Done: "**첫 오두막 상태 변화**와 두 번째 오두막 역할을 명확히 구분해야 한다."

**현재 상태** — `src/config/Chapter1World.ts:29`의 `forest.toGate` 포털에 `requireFlag`가 없다. 반면 `forest.toLogging`에는 `requireFlag:'routeKnown'`이 있다(`:30`). 따라서:

1. 플레이어가 숲 진입 직후 관문으로 직행 → `gate.inspect` → `gateChecked` 설정
2. 이후 첫 오두막에 **최초 진입** → `cabin.parchment`(`hiddenWhen:'cabinVisited'`, `:42`)와 `cabin.record`(`visibleWhen:'gateChecked'`, `:44`)가 **동시에 보인다**
3. 한 번의 방문에서 양피지와 관리 기록을 연달아 읽고 그대로 벌목로로 출발

**플레이 경험 영향** — v2가 v1에서 바꾼 유일한 GR-1 구조 변경이 무력화된다. "안전했던 공간이 다시 오니 달라져 있다"는 이 챕터의 정서적 축(문서 최종 방향: "공간을 먼저 믿게 만든 뒤 그 믿음을 배반")이 전달되지 않는다. `tests/smoke.mjs`는 의도된 순서로만 호출하므로 이 구멍을 잡지 못한다.

**권고** — `forest.toGate`에 `requireFlag:'cabinVisited'` + `denyMessage`("길은 북쪽으로 이어지지만, 먼저 저 오두막에 불빛이 있는지 확인해야 한다") 추가. 1줄 수정. 추가로 `cabin.record`의 조건을 `gateChecked`에서 "gateChecked && cabinVisited"로 강화하는 편이 안전하나, 현 `visibleWhen`은 단일 플래그만 지원하므로 `World.ts`의 타입 확장이 필요하다(S~M).

**현재 상태** — 체력 개념 자체가 없다. `src/domain/Player.ts`에 HP 필드가 없고, `src/presentation/GameController.ts:113-117` `onCaught()`은 Hollow가 `catchDistance` 26px 안에 들어온 즉시 모달을 띄우고 추격 시작점으로 되돌린다. 즉 **1타 = 즉시 실패**.

**권고** — `Player`에 `health:3`과 `lastHitAt` 추가, `onCaught()`을 "피격 → 넉백 → 무적 1.5초"로 바꾸고 0에서만 체크포인트 복귀. 2분 회복 타이머는 프로토타입에서는 생략 가능(추정: GR-1은 목표 30분이라 회복 타이머 체감 기회가 적다).
